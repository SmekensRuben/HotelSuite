Baseline: main `91c2ca96e2ecbb2743ea87903caf8b491f0c3e63` (14 October 2026, PR #242 merged). Branch: `codex/supplier-import-review-mappings-20261014`. English product/code/documentation; Dutch owner discussion. No production mutation, deployment, merge, secret read or paid provider request.

## Accepted product behavior

The upload dialog collects the supplier, file, price basis, currency and optional shared VAT. Processing continues independently of navigation. A separate import workspace shows complete-document proposal counts and a compact product list. The user can review all products or prioritize exceptions, correct one product at a time, approve or skip it, and resume saved work. Approval prepares an import; only a separate explicit final action writes supplier products. Proposed updates show the changed fields and their old/new values.

Purchase-unit mappings are hotel-, supplier-, source-format- and profile-scoped. Suggestions are proposals; only a user's confirmation creates or changes a reusable mapping. Known Sligro suggestions include FL → Bottle, ZK → Bag, EM → Bucket, BK → Box, TR → Tray, PT → Jar and ST → Piece. Unknown or ambiguous abbreviations remain review items. Applying a confirmed mapping to a draft is a separate explicit action and does not repeat a paid request or reinterpret committed products. Package labels do not establish physical contents or convert mass into count.

## Pinned contracts

New uploads require availability capability `reviewWorkspaceVersion: 1` before allocating a paid import command. Uploads carry this version and a `mappingProfileId` (default `default`); new immutable receipts/jobs store `importReviewVersion: 1` and the accepted mapping snapshot. Existing version-1/version-2 unknown acknowledgments retain their original command and fingerprint without silently adding fields. The commercial import settings remain policy 2; billing/model/budget settings are unchanged.

Proposal category (`new`, `changed`, `unchanged`, `blocked`), review status (`pending`, `approved`, `skipped`, `applied`) and actual product outcome (`created`, `updated`, `unchanged`, failed) are separate. Full-document aggregates use the protected durable review index, not the loaded page. There is no automatic approval based on an AI confidence percentage. Bulk approval is explicitly selected and constrained by server-verified eligibility. Missing prices can remain unknown in inactive drafts; missing or unverified required evidence cannot be approved as valid.

Confirmation recovery persists only scoped request IDs and row/revision references. A reload replays original batches against current server authority and immutable receipts, instead of trusting browser counts or stored successful outcomes. A changed selection cannot replace an unresolved original confirmation. Saved mappings use separate command receipts; applying them to a reviewed draft remains non-billable.

## How to use and maintain the workflow

Open Supplier Products → Import → AI Import, select the supplier and pricing context, and upload the document. The dialog closes after its countdown; processing continues when navigating. The global status indicator or Recent AI imports opens `/catalog/supplier-products/imports/:jobId`. Internal provider costs remain visible only to the platform operator through the existing operator surface.

The workspace shows proposal counts, review counts and actual import outcomes separately. Review one product, correct only necessary fields, then approve, skip or save it for later. For an existing offer, compare changed fields with the saved values. Bulk approval accepts explicitly selected, server-verified safe rows only. Import approved products is a separate confirmation; approvals alone do not change the product catalog. A rejected application must be explicitly revalidated or skipped; a browser reset cannot bypass the failure.

In Purchase-unit mappings, choose an English label, optionally select Save this mapping for this supplier and file format, and use Confirm & apply. The unchecked option applies to this import only. Sligro abbreviations are suggested, never silently saved. Saved mappings can be edited with supplier-product update permission. Save for future imports changes only the revisioned profile; Apply saved rule to this draft is a separate action. Human package corrections, skipped/applied rows, physical contents and unrelated corrections are preserved. Mapping a package does not establish a valid price or an ingredient conversion.

Profiles and their operation/audit collections are hotel-private server-owned data. A new upload freezes the accepted mapping snapshot; changing a rule cannot silently reinterpret historical or in-flight imports. Private draft/index/receipt row contents are cleaned up at expiry in bounded resumable batches. Billing evidence, immutable command fingerprints and committed product receipts remain available. No Firestore Rules or index files changed, so this feature introduces no additional Rules rollout or manual per-hotel setup.
