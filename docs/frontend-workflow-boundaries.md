# Frontend workflow boundaries

The supported browser entry is `src/main.jsx` → `src/App.jsx` → `src/AppRouter.jsx`. The 82 routed page modules load through `React.lazy`; existing `ProtectedRoute` checks still run before a protected page renders. The Suspense boundary exposes a loading status while an authorized page module downloads. This changes bundle loading, not tenant authorization or subscriptions.

| Boundary | Contract |
| --- | --- |
| Revenue quote input and analysis | `GroupQuoteCreatePage` orchestrates source queries and pure pricing engines. An unavailable analysis saves only as `analysisStatus: UNAVAILABLE`, `draft: true`, with its reason and input snapshot. It cannot expose current pricing. Required unknown inventory/OTB values remain missing before forecast normalization. |
| Quote history | Detail/outcome pages consume saved snapshots. They never silently recalculate historical analysis with a newer model. Input edits invalidate saved analysis. Unavailable and stale records visibly suppress current advice. |
| LOS preparation | `createLosNetworkHorizon` supplies a core demand/fit horizon and its complete valuation tail. Production annual preparation lives in the backend shared preparation module; frontend network valuation consumes its versioned aggregate. |
| Catalog queries and export | Current paginated filters affect the visible table. **Full export includes every product in the selected hotel and ignores those filters.** Both exporters traverse all pages through `collectPaginatedProducts`, and write a file only after the traversal completes. |
| Catalog mutations | Hotel changes reset filters, dialogs and parsed imports. Parse/import/export completions from an inactive page cannot affect the new page or write its export; export traversal stops before another page request. Product and supplier deletion failures expose retry, and obsolete deletion completion cannot navigate the active hotel. |
| Catalog and contract taxonomy | Independent `getCatalogTaxonomy` / `getContractTaxonomy` queries provide categories and subcategories; page rows cannot determine available facets. Historical free-text catalog classifications remain displayable. |
| Opera employee mapping | Operational consumers use `getOperaSettings`, which returns only `operaUserMappings`. They do not load the former mixed private settings document. |
| Staff display | Procurement pages call the hotel-scoped minimal staff display projection. Detail/edit pages load optional names independently through `useStaffDisplayNames`; the order list uses a separate scoped batch query. They retain saved names or IDs when the projection fails and ignore previous-hotel labels. Core order loading never waits for staff labels. They do not scan global profiles or resolve an email against other hotels. |
| Order detail and edit | Core record failures expose retry. Hotel/order changes reset editable dates, lines and dialogs; obsolete action completion cannot navigate a newly selected hotel. Supplier enrichment requires `suppliers.read`; frozen names/IDs remain available without it. Approval lookup runs only with `orders.approve`. Dispatch polling retains the current-scope record and dialog during refresh failures. |
| Scoped asynchronous state | `useScopedAsync` resets visible data on scope changes, completes rejected loads, supports retry, and ignores obsolete hotel/filter/page responses and callbacks invoked after their scope has changed. Its `load` callback must be memoized with every source dependency. The request scope must contain hotel and relevant resource/filter keys. Optional `retainData` preserves same-scope data during refresh/error; it never retains another scope's data. |
| Shared shell | The catalog, supplier-product, order-list and quote create/detail/edit slices use `PageShell`, which owns the header/date/logout behavior. Other existing shells remain unchanged until their workflow is migrated. |
| Heavy exports | Catalog/supplier spreadsheet imports/exports, upsell audit exports, and order PDF exports load their heavy dependency only when invoked. |

`src/hooks/useInventory.js` contains a historical router-shaped module and is not the application entry. Older service modules such as `firebaseIngredients`, `firebaseArticles`, `firebaseRecipes`, `firebaseSalesPromo`, `firebaseUsers` and `ordersAdapter` are outside the baseline entry-point import graph. This documentation does not authorize their execution, establish runtime exposure, or delete historical data. Route reachability and explicit service callers determine the live product boundary; retain any compatibility code only when a documented consumer needs it.

The focused regression suites cover missing-source draft saving, failed and reversed scoped loads, optional staff-name failures, hotel changes during an order save, read-only roles without supplier access, failed dispatch polling, complete export beyond 50 rows, independent later-page taxonomy, outcome/observation save recovery, explicit-zero evidence, and route loading behind access checks. Normal browser acceptance across two hotels, release bundle measurements and deployed backend/rules parity remain separate checks.
